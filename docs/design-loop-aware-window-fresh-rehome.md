## Overview

v0.1.6 landed and behaves as specified where it could be seen: `tcp_notsent` ≈ 0 with `bbr` on every path, `ack_after_fin` firing (2.1k/h Hytron server), `frame_send_drop` ≈ 0 outside bursts, Yuusei's fastest single hop **11.3 MB/s** (2.2 GB, was 5.1 MB/s), Hytron night-time hedge/stream 0.16 (was 0.40), leftover/Reset invariants unchanged. The user-visible goal — a large download on Hytron running at link rate — did **not** happen: same-hour hops on the same origin run 9.3 MB/s once and 200–400 KB/s three times; p50 of ≥ 8 MB Hytron downloads is unchanged at ≈ 300 KB/s.

Seven holes explain it. Five are mechanism defects in what v0.1.6 added or left, two are observability bugs that hid them. None is tuning.

1. **P3b's probe cannot succeed when the loop is longer than the RTT.** `tune_recv_cap_sampled` (`streams.rs` L709–784) doubles `recv_cap` for `4 · min_rtt` (≈ 44 ms on this pool) and keeps it only if delivery during those 44 ms was not ≥ 10 % worse than before. A stream whose ACK loop is 150–400 ms (TCP recovery on the sticky, below) cannot show any change in 44 ms; the probe measures noise and reverts. Production: **79 % of probes reverted** (Hytron server 5017 probes/h, 1105 kept), `window_limited_with_room / window_blocks = 1.00` on every instance, `recv_cap_max_bytes` histogram all zero (bug 5). The base formula `2 · rate · rtt_arrival` is still evaluated against the *quiet* path RTT (6–15 ms) — at 300 KB/s that is 3–9 KB, so the cap is the 128 KiB floor, and a stream whose pieces sit behind a 200–400 ms recovery hole is bounded at `128 KiB / hole ≈ 320–650 KB/s`. That is the observed p50.
2. **Bulk placement is blind to the loaded loop.** `path_score` (quiet RTT + `load_term`) and `bulk_overflow_pick` (`scheduler.rs` L263–289) see all eight Hytron paths as one class at 6–15 ms. `TCP_INFO` during the 02:40Z concurrent downloads (server): `soy#0` / `yuntu#0` / `yuntu#1` **660 / 411 / 253 retransmits in 3 min**, `ack_rtt` **170 / 193 / 153 ms** on `soy#0` / `yuntu#0` / `akcdn#1` while `tcp_rtt` is 13–15 ms and `notsent` ≤ 7 KB; `nsix#*` at 11.6 ms ack loop, 0 retrans. A low-rate TCP that loses a segment recovers by RTO/TLP (≥ 200 ms), and every overlay piece queued behind it on that 5-tuple waits. The scheduler keeps sticking and overflowing bulk onto those paths because nothing it reads distinguishes them; with in-order delivery at the receiver, one such piece holds the whole stream's `recv_next` and — through hole 1 — the whole window.
3. **P2 budget growth never runs.** `note_budget_limited` (`path.rs` L354) is called from `send_data` only in the branch where **no path in the pool** had room (`streams.rs` L261–273). A sticky at budget diverts to an overflow sibling without marking itself limited, so `end_budget_round` sees `limited == false` every round and takes the unlimited branch (hold, then shrink toward `2 × carried` after `BUDGET_IDLE_SHRINK` rounds — a no-op at the floor). Production: `nya_path_budget_bytes` avg **exactly 65 536** on all 24 paths across 19 h; max ever 144 KiB. The controller of the predecessor's P2.2 has not executed once in production.
4. **Hedge-on-silence rehomes onto silent paths and doubles the backoff each time.** `retry_expired_unacked` (`mod.rs` L769–962) requires `is_loss_fresh(alt)` only for `why == "belt"` (L914–920). For `"silence"`, `"down"`, `"gone"`, `"dropped"` the alt from `pick_retry_tried` may itself be silent — exactly the state during a **correlated-silence hold** (`steer.rs` L29–40: N−1 paths quiet, teardown held up to `all_down_timeout` = 8 s; Hytron 79 episodes/h, Yuusei 139/h, Datawave 3 during its 20–22Z incident). The copy is buried, `tried` grows, and the next rung waits `base × 2^(rung−1)` capped at `down_timeout_ceil` = 5 s: 320 → 640 → 1280 → 2560 ms. Production: `stall_ms` > 1 s share **Hytron client 42 %, Datawave 25–45 %** (v0.1.5 same hours 6–9 % / 0 %), the 2–5 s bucket dominant; hedges fell 20–70 % at the same time. v0.1.5's per-piece 20 ms clock reached the one live path within ≈ 160 ms at the cost of 8 copies; v0.1.6 makes 1–2 copies and takes 2–5 s.
5. **Two histograms are dead and the P6 hop attributes are lost at stream end.** `aggregate_snapshot` (`mod.rs` L2152–2158) seeds four histograms with `HistSnap::zeroed` and leaves `ack_loop_ms` and `recv_cap_max_bytes` at `Snapshot::default()` (empty buckets); `HistSnap::merge_add` (`metrics.rs` L122–124) is a no-op on empty buckets. Server `nya_ack_loop_ms` is therefore all zero on every instance (the client, which calls `snapshot()` directly, reports it). `recv_cap_max_bytes` is additionally **never observed** anywhere. And `stream_stats(stream_id)` at copy end (`outbound.rs` L133, `inbound.rs` L274) reads the live map entry, which is removed by `maybe_count_graceful → remove_held_stream` (`streams.rs` L492–503, reached from `close_send` / `apply_recv_fin`) as soon as both FINs are accounted — usually *before* the copy task returns — or by `spawn_pump`'s `reap_stream` (L170); either way a race the transfer end usually loses: **93 % of Hytron server large hops and 75 % of client ones carry no `nya.limiter`**, including every slow download listed above.
6. **"Silence" is shorter than the probe cycle.** `retry_after_bulk` (`mod.rs` L698–706) clamps `2 · ack_rtt` to `[loss_timeout(min_fast), down_timeout]` — 20 ms on this pool — while `ping_interval_max` is 50 ms. An idle-ish path is legitimately "silent" for 20–50 ms between Pongs, so any piece older than 20 ms whose ACK has not returned is re-sent. On a slow-origin stream (Yuusei 12 GB at 248 KB/s, one 16 KiB piece per 66 ms) that is **5.7 hedges per stream, 10.2k/h**, and duplicate bytes **3.7–5 %** (goal ≤ 2 %). The session's own definition of "this path is quiet" is `degrade_timeout` (probe cycle + RTT, ≥ `ping_interval_max`); the hedge uses a shorter one.
7. **The same short clock decides "fresh" for destinations.** `is_loss_fresh` (`scheduler.rs` L313–315) is `last_rx_ago < loss_timeout(min(fast, class))` = `max(2 · rtt, 20 ms)`. Pings are idle-gated at `probe_interval = clamp(rtt, 10, 50 ms)` (`path.rs` L726–728, `health.rs` L29–31), so an *idle* healthy path's `last_rx_ago` cycles up to `probe + rtt ≈ 2 · rtt` — the freshness boundary itself. `bulk_affinity` (`mod.rs` L573) drops the sticky when it is not fresh, `bulk_overflow_pick` (L275) and `pick_retry_path` rungs 1–2 skip non-fresh dests. A slow-origin bulk stream (one piece per 66 ms) therefore finds its sticky "not fresh" between pieces; `bulk_affinity` returns `None`, `bulk_overflow_pick` hands the piece to whichever fresh sibling scores best (`overflow = true`, sticky unchanged, `streams.rs` L239–246, L303–305), and the next piece repeats the draw: pieces spray across the pool as a stream of "overflows" from a sticky that is never actually full (`nya.paths_used` = 16 on Hytron's 217.116.175.244 hops), which manufactures the reorder holes of hole 1 and defeats affinity/HOL. Hole 6 is the same clock on the *source* side.

Two things are **not** holes: `path_down` doubling tracks IX conditions (identical diurnal shape in v0.1.5), and Hytron client `tcp_retrans` 25 % of tx segments is a new gauge with no baseline — it is evidence for hole 2, not a regression.

### Root cause, one level down

The seven holes are what v0.1.6 *did*; underneath them is what the fan-out design *is*. A path's budget floor is 64 KiB ≈ 43 MSS. A TCP flow that thin at 1–2 % loss cannot recover by RACK / fast retransmit (it needs data in flight past the loss and a full RTT of new data); it recovers by TLP/RTO, ≥ 200 ms. The 150–190 ms `ack_rtt` at a 13 ms `tcp_rtt` in the evidence table is exactly that — not "bad paths" but **thin flows on lossy paths** — and spraying one stream across 8–16 such flows (hole 7) manufactures the holes hole 1 then fails to cover. That reorders the value of the fixes: **P4** (budgets actually growing ⇒ fatter flows ⇒ RACK instead of RTO), **P7** (one sticky ⇒ one flow carries the stream) and **P2** (a window that covers whatever recovery remains) attack the cause; **P3** avoids the symptom and is insurance; P5/P6 fix the hedge clock, a separate defect. The strategic direction this implies — *concentrate bulk on fewer, fatter TCPs and fan out only when one is full* — is out of scope here, but every choice below is made so as not to move away from it (fit-or-**wait** for overflow, P3.2; one re-stick per stream per window, P3.3), and the PR order puts P4/P7/P2 before P3.

### Why a window follows the loop and not the RTT

The receiver window must cover everything the sender has emitted that the receiver has not yet handed to the application. With in-order delivery, that is `rate × (time from send to in-order delivery)`. When a piece sits behind a TCP RTO on one 5-tuple, that time is the RTO, not the path RTT; every later piece on every other path is held too. The predecessor's P3a changed *which* RTT the formula reads; the quantity it needs is not an RTT at all. It decomposes into two parts the receiver can see: the arrival path's RTT (already read via `bdp_rtt`) and the time in-order delivery spent waiting for a missing piece — the **hole**. The receiver knows exactly when a hole opens (a piece lands above `recv_next` while nothing is missing) and when it closes (the piece at `recv_next` lands), so `hole` is a direct measurement, not an inference from edges. (The first draft derived the loop from P3b's edge ring; review round 1 showed that estimate is biased both ways — retreating edges during a hole match late pieces and read short, and with 16 KiB edge spacing every in-order arrival matches *some* edge and reads `W / rate`, which is `2 · W` after the gain in every regime. The edge ring is removed.) No probe is needed to decide whether to keep a larger window: with per-path budgets bounding the wire (v0.1.6 P2), a larger window is memory, not queue, and the only reason to shrink it is an application that is not reading — which the receiver also sees directly, as in-order bytes it holds that the app has not taken.

### Why placement must see the loaded loop

`ack_rtt` is already per path and already loaded (bulk send → ACK, un-hedged pieces only). A path at `ack_rtt = 170 ms` with `min_rtt = 13 ms` is either queueing 12 RTTs behind other traffic on the same TCP or in loss recovery; either way it should not receive new bulk while a sibling at 12 ms has room. What is `ack_rtt` for placement? By Little's law a path we keep saturated sits at `ack_rtt ≈ inflight / throughput`: it **is** the expected sojourn of the next piece, whatever the cause — recovery, foreign queue, or simply a slow link. Any *absolute* bound built from the path's own quantities (`k · min_rtt`, or `min_rtt + budget / bw_max`) normalises in steady state, because the budget controller keeps `inflight ≈ budget` and `bw_max` follows the delivered rate — after 10 s a path stuck in recovery is "fit" by its own yardstick (review rounds 1–4). The question placement actually asks is *relative*: will this piece complete sooner here or on a sibling? So the bound is the pool's best expected sojourn, `pool_ref = min over alive, schedulable paths of ack_rtt_fresh().unwrap_or(min_rtt())` (an idle path's expected sojourn is its quiet loop), scaled by the **existing** backup rule `is_backup(cfg, ack_rtt, pool_ref)` = `ack_rtt > 2 · pool_ref + 20 ms` (`health.rs` L33–39, `tuning.rs` L98–99 — the same scale that already decides whether a path's quiet RTT makes it a backup). On this pool: `pool_ref` ≈ 12–13 ms (an idle `akcdn`/`nsix`), bound ≈ 45 ms; `soy#0` at 170 ms is unfit for as long as it stays at 170 ms, a healthy saturated sticky at `≈ 2 · min_rtt` = 26 ms is fit, a healthy slow link (1 MB/s, 64 KiB budget ⇒ 64 ms) is unfit *relative to an idle 13 ms sibling* — correctly: its pieces complete later — and gets bulk only as a *home* when no fit path can be one (fit-or-all for homes); it does not receive overflow (fit-or-wait, KD5). A single-path pool is its own reference; a pool where every path is in recovery makes the least bad one fit.

### Why "fresh" must apply to every rehome

The predecessor's R6/R8 argued that a fresh TCP delivered every earlier frame, so a copy on a fresh path is the only copy that can help. It applied that reasoning to the *source* (hedge only when the source is silent) and to the *belt* destination, but not to the *silence* destination. Under a correlated hold most paths are silent by definition; picking among them by `pick_retry_path` score is picking where to bury the copy.

## Goals & Non-Goals

**Goals**

- G1 A single bulk stream on a pool with ≥ 1 fit path is bounded by `min(origin, Σ fit paths' TCP delivery)` — literally, since overflow is fit-or-wait — not by `initial_window / recovery-hole` and not by the worst path's RTO. Acceptance: Hytron ≥ 8 MB downloads p50 ≥ 3× v0.1.6 p50 in the same hour band when `nya.limiter ≠ origin`; on the e2e `bulk_bottleneck_lossy_sibling` scenario (one path 2 % loss + 200 ms RTO, three clean at 50 Mbit/s), goodput ≥ 0.8 × 2 links (the `bulk_fanout_three_paths` precedent; re-calibrated against a clean 4-path run before tightening).
- G2 `window_limited_with_room / window_blocks` on ≥ 8 MB hops ≤ 0.2, `recv_cap_max_bytes` p50 on those hops > floor, and no probe machinery to revert.
- G3 `budget_bytes` above floor on the busiest path during any ≥ 8 MB hop (the controller runs).
- G4 `stall_ms` > 1 s share back to ≤ v0.1.5 night levels (Hytron ≤ 10 %) while hedge/stream stays ≤ v0.1.6 (0.16). During a correlated hold, pieces reach the survivor within one `retry_after_bulk` of the hold's start.
- G4b A slow-origin bulk stream keeps one sticky between pieces: `nya.paths_used` ≤ 2 on ≥ 8 MB hops with `nya.limiter = origin` and `nya.budget_diverts = 0` and no `path_down` during the hop (today 16). Fast hops fan out by design (window > one budget ⇒ overflow) and are not in this goal.
- G5 `dup_rx_bytes / bytes_data_rx` ≤ 2 % on every instance, including slow-origin streams.
- G6 Every `nya.hop` span with ≥ 1 MB in either direction carries `nya.limiter` and the wait-time attributes; server histograms non-zero; `stall_kind` and `resend_why` counters exist. Acceptance: attribute presence ≥ 99 % on large hops.
- G7 v0.1.3–v0.1.6 invariants preserved: leftover `held == live`, hop RST ≈ 1/h Yuusei, 204 first-byte, `failbacks = 0` in soak, all-down semantics, interactive TTFB doors.

**Non-Goals**

- Fixing an origin that delivers 250 KB/s to HK (P1 will *name* it; the overlay does not multiply origin bandwidth).
- Pacing, multiple TCP connections per path, protocol v3, "fewer, fatter TCPs" as a scheduling strategy (named in "Root cause, one level down" as the direction; not built here).
- Retuning any `Tuning::STANDARD` field or `path_score` weight.
- Interactive placement, affinity, hedge clock (unchanged from v0.1.5/v0.1.6).

## Key Decisions

| # | Decision | Why |
| --- | --- | --- |
| KD1 | **Attribution first, by time.** `nya.limiter` is derived from where the copy task *waited* (`origin_read_wait`, `overlay_write_wait`, …), refined by stream counters; not from counters alone. | Counters say what blocked at least once; time says what bounded the transfer. A download blocked by the window for 3 of 40 s and by the origin for 30 s is origin-limited. |
| KD2 | The receiver window is **flow control for the application**, sized by the measured loop; congestion is the budget's job (v0.1.6 P2) and the kernel's. | Removes the P3b probe and its time-base problem; makes the window monotone under a healthy app. |
| KD3 | `loop = rtt_arrival + hole`; `hole` is the receiver's **direct measurement** of how long `recv_next` waited for a missing piece (open → close), α = 1/8 EWMA, treated as 0 after `8 · loop` without a new hole (the P3b cooldown constant, reused). No edge matching. | Zero new wire; the receiver sees both ends of a hole exactly; edge-based estimates are biased (Review log R29/B1). |
| KD4 | The app-behind test counts **in-order bytes the app has not taken**: `buffered_in` + the contiguous run at `recv_next` still in `recv_buf` (re-inserted when the inbound channel was full, `drain_recv` L646–655). Out-of-order bytes (`recv_buffered` minus that run) are the reason to grow, not to stop. | v0.1.6 counts all of `recv_buffered`, which blocks growth in exactly the reorder case; `buffered_in` alone is bounded by `chan × MAX_STREAM_PAYLOAD` ≈ 1 MiB and would go dead above a 2 MiB cap (R30/B2). |
| KD5 | **Loop-fit** (`ack_rtt` a *backup* relative to the pool's best expected sojourn, existing `is_backup` scale) is **fit-or-all for a stream's home** (sticky, HOL dest, re-stick: a stream must live somewhere) and **fit-or-wait for overflow** (a piece that does not fit on the sticky goes to a fit sibling with room or parks on `budget_wait`; it is never spread onto an unfit path). Unfit paths still carry interactive/Close/Reset/retries as today. | Fit-or-all for overflow would make holes a steady-state feature: the window grows to cover pieces overflowed onto recovering paths, the larger window overflows more (architecture review M3). Fit-or-wait bounds a stream by Σ fit paths' delivery — G1 as written — never by the worst path's RTO. When every loaded path is unfit the least-bad is fit by construction (relative bound), so "wait" only happens while the fit paths are genuinely full. |
| KD6 | Unfit sticky ⇒ **re-stick**, not migrate: pieces already sent stay where they are; only new pieces move. | Same shape as `hol_bulk` (`maybe_hol`); no duplicate DATA. |
| KD7 | `ack_rtt` **expires** only when the path has **nothing outstanding** (`inflight_bytes() == 0`) and `bw_window_us` (`max(10 · rtt, 100 ms)`) has passed without a sample; while pieces are outstanding and unsampled the expected sojourn is `max(ack_rtt, last_rx_ago)`. The last value is retained on expiry and, for placement, decays toward `min_rtt` over `MIN_RTT_WIN_US`. | "No sample" means two opposite things: idle (nothing to sample) or stuck in RTO (the ACK has not come back). `ack_rtt` is fed only by un-hedged bulk ACKs, so a path in a 200–400 ms RTO is silent for longer than `bw_window_us`; expiring it there would call the path fit exactly while it is stuck (round 5 M1). With bytes outstanding, `last_rx_ago` is a lower bound on the current loop. Snapping an idle path to its quiet RTT makes every idle path look best under pool-wide loss (architecture review M1). |
| KD8 | Fresh-alt for **all bulk** `why`; the exponential rung is `belt`-only; silence rehomes re-arm on the alt's own `retry_after_bulk`; interactive `age` rehomes unchanged. | The rung exists to bound receiver-drop storms on a healthy path. Under silence the alt's own silence clock is the right wait. |

## Proposed Design

### P1 — Attribution that survives stream end and is measured in time

**P1.1 `TunnelStream` owns the stream's counters.** The atomics `StreamStats` reads (`recv_cap`, `send_window`, `window_blocks`, `budget_blocks`, `window_limited_with_room`, `recv_cap_max`, `hedges`, `dup_rx_bytes`, `paths_used`, `send_next`, `recv_next`, plus the P1.4 additions) move into `pub struct StreamCounters` held by `StreamState` as `counters: Arc<StreamCounters>`; `TunnelStream { id, inner: DuplexStream, counters: Arc<StreamCounters> }`, constructed in `try_alloc_local_stream` (`streams.rs` L77–91) where `st` is already in hand. `TunnelStream::stats(&self) -> StreamStats` and `HopProbe::inner(&self) -> &T`. `outbound.rs` L133 and `inbound.rs` L274 (`copy_with_hop`) read `overlay.inner().stats()` instead of `session.stream_stats(stream_id)`. `Session::stream_stats` stays for `all_stream_stats` / debug. **Why not `Arc<StreamState>`:** Close/Reset are delivered to the pump with `inbound_tx.try_send` (`streams.rs` L1041, `mod.rs` L1707/L1768/L1787) and are silently dropped when the channel is full; the pump's recv loop (L151–167) then ends only when the last `Sender` — inside `StreamState` — drops, which today happens at `remove_held_stream`. A `TunnelStream` holding `StreamState` would keep that `Sender` alive until the copy task ends, and the copy task waits for the pump's duplex half: a cycle. `StreamCounters` holds no channel, no buffers, no `Notify` — atomics plus the bounded `paths_used: Mutex<Vec<u32>>` (`stream.rs` L125, L254–258). Memory: a few dozen words per live hop.

**P1.2 Pending-time accounting.** The first drafts instrumented `poll_read`/`poll_write` inside `HopProbe` and encoded tokio `CopyBuffer`'s polling pattern ("the reader is polled while the writer is Pending", write-wins) as an attribution rule — a dependency on a third-party implementation detail, on the measurement every later decision rests on. Instead `hop.rs` gets a **small two-direction copier** (`copy_bidirectional_timed`, ≈ 60 lines: one buffer per direction, `select!` over the two directions, each direction a plain read-then-write state machine) that knows exactly which future it is awaiting and bills the wait to it (architecture review N1; this reverses Alt. 7). Buffer size is **pinned to 8 KiB per direction**, the same as `tokio::io::copy_bidirectional`, because the copier's write size shapes piece sizes, `becoming_bulk` timing and hedge/dup counts — the baseline the 24 h gate is read against must not move; `timed_copier_close_semantics` also asserts the piece-size distribution on a fixed input equals the tokio copier's. Wait time is then **per transfer direction** with one blocker at a time by construction. A direction is the pair (reader probe, writer probe): server download = (origin.read, overlay.write); server upload = (overlay.read, origin.write); mirror on the client. Each direction keeps `read_wait_us`, `write_wait_us` as plain fields of the copier's state (single task, nothing shared, no atomics); the copier returns them with the byte counts. Both server (`outbound.rs` L133) and client (`inbound.rs` L268) call the new copier in place of `tokio::io::copy_bidirectional`; the `HopProbe`/`HopClock` wrappers stay for `first_rx`/`first_tx`/bytes as today, and the client's raw app `TcpStream` needs no wrapper — the copier itself times its reads and writes. Per direction the copier is either awaiting `read` (buffer empty) or awaiting `write_all` (buffer full) — never both — so the wall time of each await is added to exactly one counter. `flush`/`shutdown` are not counted. The hop reads both directions' `(read_us, write_us)` from the copier's result.

Attributes on `nya.hop`:

| Server | Client | Meaning |
| --- | --- | --- |
| `nya.origin_read_wait_us` | `nya.app_read_wait_us` | waited for the far side to produce bytes |
| `nya.origin_write_wait_us` | `nya.app_write_wait_us` | waited for the far side to accept bytes |
| `nya.overlay_read_wait_us` | same | waited for the tunnel to produce bytes |
| `nya.overlay_write_wait_us` | same | waited for the tunnel to accept bytes (duplex full ⇒ pump blocked in `send_data`) |

`copy_bidirectional` polls both directions in one task; the two directions' waits overlap and their sum can exceed `copy_us` — the attribution uses the *dominant* direction (`rx_bytes` vs `tx_bytes`) and only its two waits.

**P1.3 `nya.limiter` redefined.** The mapping is keyed on whether **this side is the overlay sender or the overlay receiver for the dominant direction**, not on role:

| role × dominant | this side is | `far` (produces the bytes) | `near` (consumes them) |
| --- | --- | --- | --- |
| server, `rx_bytes` (origin → us: download) | overlay **sender** | `origin_read_wait` | `overlay_write_wait` |
| server, `tx_bytes` (us → origin: upload) | overlay **receiver** | `overlay_read_wait` | `origin_write_wait` |
| client, `rx_bytes` (overlay → us: download) | overlay **receiver** | `overlay_read_wait` | `app_write_wait` |
| client, `tx_bytes` (us → overlay: upload) | overlay **sender** | `app_read_wait` | `overlay_write_wait` |

(`rx_bytes`/`tx_bytes` are the probed socket's: the origin socket on the server, the tunnel on the client — `outbound.rs` L129–130, `inbound.rs` L286–287.)

```
if far + near < copy_us / 10   -> "none"     (waited < 10 % of its life: short/idle hop; documented threshold)
overlay sender:
    far >= near                -> server: "origin"   client: "app"      (the local far side paced us)
    else                       -> budget_blocks >= window_blocks              -> "budget"
                                  window_limited_with_room*2 >= window_blocks -> "window"
                                  else                                        -> "path"
overlay receiver:
    far >= near                -> "overlay"   (the tunnel paced us: read the peer's span)
    else                       -> server: "origin"   client: "app"      (the local consumer paced us)
```

`window/budget/path` are only ever emitted by an overlay sender, which is the side that increments those counters. An overlay receiver's "overlay" is read against the **peer's** span (same `stream_id` + `session_fp`). Old string values `window`/`budget`/`path`/`none` keep their meaning; `origin`, `overlay`, `app` are new.

**P1.4 Receiver-side evidence on the span.** Two receiver quantities are defined once and used by P1 and P2 alike: `in_order_held` = bytes of the contiguous run starting at `recv_next` in `recv_buf`, walked under the `recv_buf` lock (non-zero only when `drain_recv` re-inserted the head because the inbound channel was full); `app_backlog = buffered_in + in_order_held`; `hole_bytes = recv_buffered.saturating_sub(in_order_held)` (the two are read separately; saturate). `StreamCounters`/`StreamStats` gain `recv_hole_max` (max `hole_bytes`), `app_backlog_max`, `zero_win_hole`, `zero_win_app` (count of ACKs sent with `advertised_window() == 0`, attributed to `hole` when `hole_bytes ≥ app_backlog`, else `app`), `hole_us` (P2's `hole_ewma`; 0 until PR 5 ships), `budget_diverts` (P4; 0 until PR 3). Attributes `nya.recv_hole_max`, `nya.app_backlog_max`, `nya.zero_win_hole`, `nya.zero_win_app`, `nya.hole_us`, `nya.budget_diverts`. Counters `nya_zero_window_total{cause="hole"|"app"}`.

**P1.5 Origin socket `TCP_INFO` (server, Linux).** At copy end the `HopProbe` still owns the origin `TcpStream`; `outbound.rs` reads it through `origin.inner().as_fd()` (a `BorrowedFd`) with the existing `getsockopt(TCP_INFO)` reader generalised from `&OwnedFd` to `impl AsFd` (`net.rs` L181). No `dup`, no lifetime beyond the copy task. `TcpInfo` gains `rcv_rtt_us` (offset 92), `rcv_space` (96), `busy_time_us` (168), `rwnd_limited_us` (176), `sndbuf_limited_us` (184), `bytes_retrans` (208), `rcv_ooopack` (224); all parsed only if the returned length covers the offset. Attributes: `nya.origin_tcp_rtt_us`, `nya.origin_tcp_min_rtt_us`, `nya.origin_tcp_retrans`, `nya.origin_tcp_bytes_retrans`, `nya.origin_tcp_delivery_rate`, `nya.origin_tcp_busy_us`, `nya.origin_tcp_rwnd_limited_us`, `nya.origin_tcp_sndbuf_limited_us`, `nya.origin_tcp_rcv_space`, `nya.origin_tcp_rcv_ooopack`. For a download the server is the TCP receiver: `rcv_space`/`rcv_rtt`/`rcv_ooopack` describe the origin→HK leg; for an upload `rwnd_limited`/`sndbuf_limited`/`busy_time` say whether HK→origin was bounded by the origin's window or by us. The same fields are added to the per-path gauges (`nya_path_tcp_rwnd_limited_us`, `nya_path_tcp_sndbuf_limited_us`, `nya_path_tcp_busy_us`) and the labelled counter `nya_path_tcp_bytes_retrans_total` (as `nya_path_tcp_retrans_total`) — cheap, same `getsockopt`. No `TCP_CONGESTION` change on the origin socket (open question).

**P1.6 Dead histograms.** `aggregate_snapshot` seeds `ack_loop_ms: HistSnap::zeroed(STALL_MS_BOUNDS)` and `recv_cap_max_bytes: HistSnap::zeroed(RECV_CAP_BYTES_BOUNDS)`; a unit test asserts every `HistSnap` field of `Snapshot` has non-empty buckets after `aggregate_snapshot` of two sessions (reflection by listing fields in one place: `Snapshot::hist_fields_mut()`). `HistSnap::merge_add` adopts `other.buckets.clone()` when `self.buckets.is_empty()`. `observe_stream_end` observes `recv_cap_max_bytes` for streams with `received > 0`.

**P1.8 Falsifiers shipped with PR 1.** Three measurements move into PR 1 as observability only, because without them the 24 h gate cannot tell the causal story from its alternatives (architecture review M4/M5/N5): (a) **P2.1's hole measurement** (`hole`, `hole_ewma`, `nya.hole_us`, `nya.recv_hole_max`, `zero_win_hole`) with the window controller untouched — a slow hop with `limiter = window` and `hole_us ≈ 0` means the window is limited behind an *in-order* queue or the pump, not a reorder hole, and P2/P3 must not ship as designed (that is the null result; P2 is a bet that all loop excess not created by this stream shows up as a reorder hole); (b) **correlated-silence discriminator**: both roles log a `quiet_set` event whenever `quiet ≥ alive − 1` **including all-N** (`correlated_hold` itself never fires on all-N, `steer.rs` L28/L37 — so a host whose own process stalled sees nothing, while its peer sees all-N quiet and logs no episode today; timestamp coincidence would therefore read a local stall as network silence, the unsafe direction — architecture re-review M2). Each event carries `session_fp`, wall-clock, the quiet set, the survivor, and per-path `TCP_INFO` `retrans`/`bytes_retrans` deltas across the episode. Join rule: **network** ⇒ the peer logs the same quiet subset at the same instant and the quiet paths show non-zero retrans deltas; **local / peer-side** ⇒ the peer logs all-N or nothing, the survivor identity is uniformly random across episodes, retrans deltas are zero, and the original piece and the rehomed copy are ACKed within one tick of each other (every rehome a dup). Plus `stall_ms` conditioned on `correlated_silence`, and the time from a fresh-alt rehome to the survivor's ACK; (c) **direction check**: the mechanism is symmetric, so the 7.5 MB/s upload vs 0.3 MB/s download asymmetry means the loss is directional; client-side `nya_path_tcp_retrans_total` on uploads vs server-side on downloads must show it, or the story is wrong.

**P1.7 Stall kind and resend reason.** `scan_stall` (`steer.rs` L560) records at stall **entry** `nya_stall_enter_total{kind}` with `kind ∈ {send, send_zero_window, recv_hole, both}` — `both` when `send_origin` and `recv_origin` fired in the same scan (`steer.rs` L632–636); `send_zero_window` when only `send_origin` fired and `send_window == 0` or `!window_ok(1)`. `retry_expired_unacked` records `nya_data_resend_total{why}` (`silence|belt|down|gone|dropped|age|allquiet`) and `nya_data_resend_skipped_total{reason}` (`no_fresh_alt|allquiet_wait|queue_full|write_stalled|all_tried|no_alt`; `allquiet_wait` = KD9 fallback not yet due, `queue_full` = P5 step 2b). Labelled counters use the existing `counter_labeled` machinery (as `nya_path_picks_total`); `note_migrate` reasons are separate plain counters (`mod.rs` L1963–1971, catalog L163–183) and P3.3 adds one, `nya_migrates_loop_unfit_total`.

### P2 — Receiver window sized by the in-order delivery loop

**P2.1 Hole measurement.** `StreamState` gains `hole: Mutex<Option<(u64 /*off*/, Instant)>>` (the missing offset in-order delivery is waiting for, and since when), `hole_ewma_us: AtomicU64`, `hole_sampled_at_us: AtomicU64` (monotonic µs; atomics so `tune_recv_cap` reads them without taking a lock while it holds `recv_buf` for `in_order_held` — no lock-order hazard). The `hole` mutex is only ever taken inside `drain_recv` while `recv_buf` is held (single nesting order). The state is derived from **buffer contents under the `recv_buf` lock in `drain_recv`** (`streams.rs` L639–660), never from the landing offset of an individual piece: several path-reader tasks insert concurrently and `recv_next` advances in a separate lock acquisition, so per-insert reasoning races (round 2 M1). After `drain_recv`'s loop, still holding the lock, with `full` = the loop stopped because `inbound_tx.try_send` failed:

```
head_missing = !full && !buf.is_empty() && !buf.contains_key(&recv_next)   // scan_stall's own definition, steer.rs L604
match *hole {
    Some((off, t)) if off < recv_next || buf.contains_key(&off) => {   // the missing piece is here — closed,
        sample(now - t);                              // whether it was drained past or is the re-inserted head of a full channel
        *hole = head_missing.then(|| (recv_next, now)); // next hole behind it, or none
    }
    None if head_missing => *hole = Some((recv_next, now)),   // opened
    _ => {}                                           // same hole still open, or app-blocked with no filled hole: untouched
}
```

The first arm is keyed on the missing piece being *present* (`off < recv_next`, or `off` still in the buffer because the channel was full when it arrived), not on `full`: a drain that fills hole `X` and then stops — at `Y` after delivering a few pieces, or at `X` itself because the channel is full — has closed `X` in *this* drain and must sample now; otherwise the sample taken by the next non-full drain would include the app-blocked interval (round 3 M2, round 4 M2).

`sample(d)` folds `d` into `hole_ewma_us` (α = 1/8; first sample seeds) and stamps `hole_sampled_at_us`. A stream whose head is present but undeliverable (`full`) neither opens nor prolongs a hole — the application, not the network, is waiting; a hole it *filled* on the way is still closed and sampled. `drain_recv` runs after every first-arrival insert and from `note_app_read`, so every hole that is ever filled is closed by the drain that sees it filled; a hole still open at FIN/Reset/`expire_recv_closes` dies with the stream and yields no sample. Only first arrivals reach `drain_recv`: the replacement branch (L601–614, a re-sent piece landing on an offset already buffered) keeps today's insert-and-account (chunk replaced, `dup_rx_bytes += old_len`, `recv_buffered −= old_len; += new_len`), `send_ack`s and **returns** — it no longer falls through to `drain_recv`, and the P3b `note_arrival`/`edge_ring`/`edge_hits` machinery it fed is deleted (P2.5). A hole spanning several missing pieces yields one sample = the head's wait; when a second hole sits directly behind the first, its wait is measured from the first's close (under-estimate on overlapping losses; the next sample corrects, and the cap is monotone so an under-estimate never shrinks it).

**P2.2 Target.**

```
rtt    = bdp_rtt(st)                       // arrival path's RTT, as today (unknown ⇒ floor)
hole   = hole_ewma      if now − hole_sampled_at_us ≤ 8 · (rtt + hole_ewma)   else 0   // stale: no hole for 8 loops
loop   = rtt + hole
target = clamp(2 · deliver_rate · loop, floor, ceil)
```

`deliver_rate` is the in-order delivery EWMA already kept by `note_deliver` (α = 1/8, `stream.rs` L343–349, so `target` follows a step in rate over a few samples, not one). Regimes: (a) window-limited behind recovery holes — `deliver_rate → cap / loop` ⇒ `target → 2 · cap` ⇒ the cap grows monotonically, roughly doubling every few samples, until the sender is no longer window-limited, then (b) `deliver_rate` is the true rate and `target = 2 · rate · (rtt + hole)` = twice the BDP over the real in-order loop; (c) no holes, in-order path (the single-TCP bottleneck of `bulk_bottleneck_single`) ⇒ `target = 2 · rate · rtt`, where `rtt` = `bdp_rtt` = the arrival path's **quiet** `rtt()` (the receiver sends no Pings while bulk is arriving — Pings are idle-gated on `last_rx_ago`, `path.rs` L726–728, L1213–1218 — and `on_pong_record` *discards* samples above the cap rather than clamping, L1023–1027; so `rtt()` is the pre-transfer quiet value). Once `W ≥ BDP` the sender's loop is `L = W / bw` and `rate = bw`, so the fixed point is `W* = max(floor, 2 · bw · rtt())` with `rtt() ∈ [R_quiet, 2 · R_quiet]` (a slow window-limited stream with piece gaps ≥ `ping_every` does take Pongs during bulk, accepted up to the cap) — `W* ∈ [2, 4] · BDP`, throughput `bw` (since `W* ≥ BDP`) with ≥ one BDP of slack for jitter, **not** the floor lock (the floor lock was `W* < BDP`). What this regime does **not** get is P3b's extra: on `bulk_bottleneck_single` (50 Mbit/s, 10 ms ⇒ BDP 62.5 KB, floor 128 KiB = 2.1 · BDP) v0.1.6 measured 87 % with the base formula and 95–97 % with the probe (predecessor L49–60); P2 gives up that 8–10 % on a synthetic single path in exchange for a controller that does not revert under recovery holes. The scenario's 70 % gate stays and becomes a PR 5 door with the number recorded. The predecessor's fixed point `W' = W · 2R/L` bit because `R` was the *sender's* quiet RTT while `L` carried a queue the sender could not see; the measured hole is the part of `L` the receiver can see without inflating its own queue (Alt. 1c); the self-inflicted in-order queue is, by construction, the slack above BDP.

**P2.3 Growth, hold, shrink.** Replace the body of `tune_recv_cap_sampled` (probe machinery, `WinCtl.probing`, `hold_cap`, `hold_rate`, `last_probe_end`) with:

```
held       = buffered_in + recv_buffered                 // everything advertised-and-consumed
app_behind = app_backlog > cur / 2                        // P1.4: buffered_in + in_order_held (KD4)
if app_behind:  cap = min(cur, max(target, held))        // shrink toward target, never above cur, never below what is held
else:           cap = max(cur, target)                    // monotone up while the app keeps up
cap = min(cap, cur + session_room)                        // P2.4: bounds the *increase* only; never below cur
cap = clamp(cap, floor, ceil)
```

Properties: `advertised_window() = cap − held ≥ 0` after a shrink (it may be exactly 0; recovery is the existing `note_app_read → drain_recv → send_ack`). The shrink branch can never raise `cap` (R30); the guard can never lower it (R41). `app_backlog` is unbounded (in-order bytes accumulate in `recv_buf` up to the cap when the app stalls), so the test stays live at any cap. `recv_cap` is updated with a CAS loop (`fetch_update`), and the Δ added to `recv_cap_extra` is `new − actual_old` from that CAS, so two concurrent callers (every path-reader task's `drain_recv`, plus `maintain`; today only `win_ctl.lock()` orders them and it goes with `WinCtl`) telescope exactly and `Drop`'s `recv_cap − floor` balances the sum (round 3 M1). `in_order_held` is computed by walking `recv_buf` from `recv_next` while contiguous — ≤ `cap / MAX_STREAM_PAYLOAD` = 512 entries at the ceiling, and non-zero only while the channel is full. The rule is applied on **every** call of `tune_recv_cap` — sampled (new rate from `note_deliver`) or not (`maintain`'s `tune_recv_windows`, `steer.rs` L204, every 5 ms) — because it is idempotent: `target` only changes with `rate`/`hole`, and `max(cur, ·)` / `min(cur, ·)` make the result cadence-independent. Today's unsampled body (`cap = base.max(held)`, L777–778) is **replaced**, not kept: re-running it would reset the cap to `base` 200×/s (round 2 M3).

**P2.4 Memory guard.** `Inner.recv_cap_extra: Arc<AtomicU64>` = Σ over live streams of `recv_cap − floor`; each `StreamState` holds a clone. `session_room = (alive_paths · ceil).saturating_sub(recv_cap_extra)` (8 paths ⇒ 64 MiB; one path ⇒ 8 MiB; `alive_paths == 0` ⇒ 0 ⇒ no growth; the app-behind shrink is unaffected). The guard bounds only the **increase** in one call (`cap = min(cap, cur + session_room)`), so a sibling growing or a path going down never lowers an existing cap (round 2 M2). `tune_recv_cap` adds `new_cap − old_cap` to the sum when it raises the cap and subtracts when the app-behind rule lowers it; **`impl Drop for StreamState`** subtracts the final `recv_cap − floor`. Drop, not `remove_held_stream`: every caller of `tune_recv_cap` holds an `Arc<StreamState>` (`get_stream`, `streams.rs` L560), so a tune racing the map removal is accounted by the same Drop that runs after it — no window for a leaked Δ (round 2 M6). Gauge `nya_recv_cap_extra_bytes` = the Σ `recv_cap − floor` itself. Rationale: the pool's budgets bound the wire; the window beyond the floor exists to cover reorder holes, whose depth cannot exceed what the paths carry.

**P2.5 Removed.** `recv_cap_probes`, `recv_cap_probe_kept`, `recv_cap_probe_reverted` counters; `WinCtl` (all fields); `edge_ring`, `EDGE_RING`, `note_ack_edge`, `note_arrival`, `edge_hits`; the `tol` computation in `deliver_data`. `n_counter` and `.local/nya-signoz.py completeness` catalog updated in the same PR.

**P2.6 Sender side unchanged.** `send_window` from ACKs, `window_ok`, `send_wait` wake — as today. Cumulative `inflight_send` (SACK'd bytes still count) is correct: those bytes occupy `recv_buf`.

### P3 — Loop-aware bulk placement

**P3.1 Fit.** `PathState::loop_fit(&self, cfg, pool_ref: Option<Duration>) -> bool`:

```
loaded(p)   = match p.ack_rtt_fresh() {                       // KD7
    Some(a) if p.inflight_bytes() > 0 => Some(max(a, p.last_rx_ago())),  // outstanding and quiet ⇒ the loop is at least this long
    Some(a)                           => Some(a),
    None    if p.inflight_bytes() > 0 => Some(p.last_rx_ago()),           // never sampled but stuck: same bound
    None                              => None,                             // idle
}
decayed(p)  = min_rtt + (last_ack_rtt − min_rtt) · max(0, 1 − age / MIN_RTT_WIN_US)   // idle path: last loaded loop, decaying over 10 s
sojourn(p)  = loaded(p).or(decayed(p) if ever loaded).or(p.min_rtt())
pool_ref    = min over alive ∧ schedulable paths of sojourn(p), skipping None   // filter_map: an unknown-RTT path does not make pool_ref None
loop_fit(p, cfg, pool_ref) = match (loaded(p).or(decayed(p)), pool_ref) {
    (Some(a), Some(r)) => !health::is_backup(cfg, a, r),          // a <= 2·r + 20 ms (backup_rtt_mult/add, existing)
    _ => true,                                                     // never loaded = fit
}
```

`pool_ref` is computed once per `maintain` tick and stored on `Inner` (`pool_ref_us`); `PathState::loop_fit(cfg, pool_ref: Option<Duration>)` takes it as an argument everywhere it is called. An idle path does **not** snap to its quiet `min_rtt`: its last loaded loop decays toward `min_rtt` over `MIN_RTT_WIN_US` (10 s, the window `min_rtt` itself uses). Otherwise under pool-wide loss every idle path looks best, is loaded, turns unfit within one window, and the stream rotates through the pool while N streams herd onto the same idle path each tick (architecture review M1). With decay, a path that was at 170 ms two seconds ago still reads ≈ 140 ms and is not a home; one that was bad a minute ago is clean again.

`pool_ref` is the best expected completion time a piece could get anywhere in the pool right now; `is_backup` is the scale the session already uses to call a path a backup by quiet RTT (`steer.rs` L313–314, `scheduler.rs` L111, L797). A path is unfit only relative to a sibling that would complete the piece at least `2× + 20 ms` sooner — which is what "do not put bulk here while a sibling has room" means. No absolute bound (rounds 1–3 tried `k · min_rtt` and `min_rtt + budget / bw_max`; both normalise under Little's law once the controller holds `inflight ≈ budget`, round 4 B1). `ack_rtt_fresh()` returns `ack_rtt()` unless `inflight_bytes() == 0 && now − ack_rtt_at_us > bw_window_us()` (KD7); `record_ack_rtt` stamps `ack_rtt_at_us`; the value itself is never cleared. The two budget-controller readers switch to `ack_rtt_fresh()`: `note_bw_sample`'s `round_us` (`path.rs` L338–343, `.or_else(min_rtt)`) and `end_budget_round`'s `carried = bw · loop` (L419–420, `unwrap_or(0)` as today) — an idle path's stale loop must not stretch its first rounds. `retry_after_bulk` (`mod.rs` L702) keeps reading the retained `ack_rtt()`: shortening the silence clock on a path that has gone quiet with bytes outstanding would hedge more on exactly the paths P3 steers away from (round 5 M1). `PathState` also gains `loop_fit_last: AtomicBool` and `loop_unfit_total: AtomicU64` for the P3.4 transition counter.

**P3.0 One placement function first.** Bulk placement is decided today in `send_data` (affinity → overflow → any-room fallback), `hol_place_bulk`, `hol_place_bulk_fallback`, `maybe_hol`, `bulk_overflow_pick` and `retry_expired_unacked`, each with its own ordering of schedulable / fresh / room / quiet (`bulk_affinity`, `mod.rs` L561–581, uses yet another). The first commit of the P3 PR is a **refactor with no behaviour change**: one pure `scheduler::place_bulk(view: &PoolView, st: &StreamView, reason: PlaceReason) -> Option<Placement { path, restick: bool }>` that every site calls, applying the filters in one order (schedulable ⇒ quiet-fresh ⇒ room ⇒ fit ⇒ HOL-quiet ⇒ score) and emitting one `debug!` naming the filter that emptied the set. P3 is then a single predicate in one place, and the existing bulk e2e doors (`bulk_bottleneck_single`, `bulk_shared_two_streams`, `bulk_fanout_three_paths`, `far_peer3_slow1`) gate the refactor commit before the predicate lands (architecture review M7).

**P3.2 Fit-or-all for homes, fit-or-wait for overflow.** `scheduler::loop_fit_or_all(cfg, cands)` mirrors `loss_fresh_or_all` (L317–). `pick_pref(Any)` / `pick_from(Any)` are shared with Close placement (`streams.rs` L474), Reset placement (`mod.rs` L1792) and `failback_target` (`scheduler.rs` L598, L613) and are **not** changed. A new `Session::pick_bulk(exclude: Option<u32>)` = the `Any` candidate list → `is_schedulable()` (which already excludes write-stalled, `path.rs` L580–582) → `quiet_fresh_or_all` (P7) → `room_bytes() ≥ MAX_STREAM_PAYLOAD` → `loop_fit_or_all` → prefer `!conn_has_interactive` (the same preference `bulk_overflow_pick` applies at `scheduler.rs` L282–287, so a fit choice is not undone by `hol_place_bulk` a tick later) → `≠ exclude` → `pick_from_scored(Any)`; `None` if the room filter empties it (the order R11 gives: schedulable ⇒ fresh ⇒ room ⇒ fit ⇒ quiet ⇒ score).

Where a bulk stream's sticky is actually chosen today (round 2 M4): the **first** bulk piece is placed with `pref == Interactive` (`streams.rs` L219–223 reads `st.bulk` before the `becoming_bulk` swap at L285–286), i.e. by interactive affinity / `pick_pref(Interactive)`; `hol_place_bulk` (`steer.rs` L412–429) moves it only when that path carries interactive; the `pick_pref(Any)` fallback at L249 runs only when affinity is `None` *and* no overflow sibling has room. So the fit gate is applied where bulk is decided: (i) **`becoming_bulk`** (L285–305): nothing has been sent yet at this point (the send is L335) and the block ends with `if !overflow { set_sticky(id, path_id) }` (L303–305). After the existing HOL move has (or has not) redirected `path_id`: if `!path(path_id).loop_fit()` and `pick_bulk(Some(path_id))` returns `f` **with `f.loop_fit()`** (`pick_bulk` is fit-or-all and may return an unfit path when nothing else is fit — then leave `path_id` alone), set `path_id = f`, `overflow = false`, `note_migrate("loop_unfit")` — the first bulk piece then goes to `f` and L303 sticks it there. Order is HOL first, fit second (a HOL dest that is itself unfit is corrected by the fit step; a fit sticky that carries interactive is still moved by HOL as today); (ii) `hol_place_bulk` / `hol_place_bulk_fallback` dest choice adds `loop_fit_or_all` over its own candidate list, with `hol_bulk_dest_ok` (`scheduler.rs` L438–443) moved to `is_quiet_fresh` (P7); (iii) `bulk_overflow_pick` — **fit-or-wait**: unfit paths are removed from the overflow candidates (after the room filter, before the interactive-quiet preference); if nothing fit has room the piece parks on `budget_wait` exactly as it does today when nothing has room (`any_bulk_room` guard, `scheduler.rs` L291–296, now evaluated over fit paths), so no new wait path is introduced; (iv) the L249 fallback is split by **why** the stream got there. If the sticky exists but was full (`bulk_affinity` returned `Some`, room rejected it — the overflow case): the fallback is **overflow too** — fit-only, room ≥ `MAX_STREAM_PAYLOAD`, else park on `budget_wait`; it never calls `set_sticky`. Without this split the chain sticky-full → overflow-pick empty (fit siblings at 1–16 KiB of room) → `any_bulk_room` true → `pick_bulk` (room filter before fit) returns an *unfit* path and, because `overflow == false` on that branch, `set_sticky` homes the stream there and bumps `last_stick_change`, so P3.3 cannot undo it for 10 s — the exact case fit-or-wait exists for (architecture re-review M1). Only if the stream has **no** sticky (`bulk_affinity` = None: first bulk piece, sticky gone) does the fallback re-home: `pick_bulk(None).or_else(|| pick_pref(Any))` (fit-or-all) inside the existing `any_bulk_room` guard (L247–253). Unit test `overflow_fallback_never_resticks_unfit`. P3.3 covers a sticky that turns unfit *later*. Interactive candidates, `pick_retry_path` (P5 decides there), `should_rebalance_conn` (interactive, stays on `is_loss_fresh`) and failback are untouched.

**P3.3 Re-stick.** In `maybe_hol` (`steer.rs` L431) for `st.bulk`: if `!cur.loop_fit()` and a path `p` in `fastest_class_set` with `p.loop_fit() && p.is_schedulable() && is_quiet_fresh(p) && room_bytes() ≥ MAX_STREAM_PAYLOAD && !conn_has_interactive(p)` exists — where a **dest**'s fitness uses `loaded(p).or(decayed(p))` like everything else: a path that drained and went idle keeps its (decaying) last verdict, so two unfit paths cannot hand a stream back and forth on the expiry clock (round 5 M2). Fit-or-all here means *stay put*: no fit dest ⇒ no move — `set_sticky(st.id, best_by_score(p))`, `note_migrate("loop_unfit")` (new plain counter `migrates_loop_unfit`, exported `nya_migrates_loop_unfit_total`), `hol_rebalances += 1`. Once per `maintain` tick per stream, at most **one incoming `loop_unfit` re-stick per destination path until that dest has recorded ≥ 1 `ack_rtt` sample since the last incoming re-stick, and never more than one per `bw_window_us(dest)`** (whichever is later — a hold of only `bw_window_us` ≈ 100 ms is shorter than one loaded loop, so N streams would still herd onto a never-loaded sibling within a second; architecture review M1 / re-review N1), and at most **one `loop_unfit` move per stream per `MIN_RTT_WIN_US`** (10 s): a re-stuck stream lives with its choice long enough for the new sticky's loop to be judged on its own samples. `stick_changed_ago_ge` (`stream.rs` L295–297; today only used by the dead `maybe_failback`) carries the per-stream hold; `maybe_hol` itself has no hold today. Pieces already on `cur` stay (KD6). `hol_rebalances` is **not** incremented for this move — `nya_migrates_loop_unfit_total` counts it.

**P3.4 Observability.** Gauges `nya_path_loop_fit{path}` (0/1) and `nya_path_min_rtt_us{path}` (the overlay's windowed min loop RTT; with the existing `nya_path_ack_rtt_us` the pool reference and the `2× + 20 ms` bound are checkable from Signoz); counter `nya_path_loop_unfit_total{path}` (fit → unfit transitions, sampled in `maintain`); `nya.paths_used` already on spans.

**P3 × P4.** P4 growth raises a healthy sticky's `ack_rtt` toward `2–3 · min_rtt(sticky)` (one to two BDP of standing queue, `BUDGET_CAP_GAIN = 3`). The margin against the bound is `2 · (pool_ref − min_rtt(sticky)) + 20 ms − queue beyond 2 · min_rtt`: when the sticky is on (one of) the pool's fastest paths this is ≥ 20 ms and it stays fit; when it started on a slower same-class path beside a faster idle one (Hytron: 13 ms `nsix` beside 7 ms `yuntu#1`, bound 34 ms), a fully grown budget (≈ 39 ms) makes it unfit **once** and the stream moves to the faster idle sibling. That move is intended — the faster path completes pieces sooner — and it converges (the fastest loaded path is under `2 · its own min_rtt + 20 ms`); it costs one re-stick per such stream, which the `< 1 per bulk stream` door tolerates. Unit test `restick_once_to_faster_idle_sibling` (7 / 13 ms pool, budget at the cap) asserts exactly one move. **Known limit — reverse traffic**: `ack_rtt` is measured send → ACK-arrival, and the ACK rides the reverse direction of the same TCP; a path also carrying *reverse* bulk adds the reverse `NOTSENT_LOWAT` queue (64 KiB / bw) to every forward ACK, so P3 over-estimates the forward sojourn on bidirectional pools and may call every such path unfit — fit-or-all for homes and the per-stream/per-dest holds bound the damage to "today's placement", and e2e `bulk_bidirectional_same_pool` (below) is the door (architecture review M2). Limit: `min_rtt()` is a 10 s windowed min of loop samples fed by every un-hedged data ACK and Pong (`note_loop_rtt`, `MIN_RTT_WIN_US`); a path whose *every* round trip has been inflated for > 10 s normalises to "fit" — at that point its `rtt()`/class also reflect the inflation and the existing class/backup machinery, not P3, is what keeps bulk off it. Test `bulk_fanout_three_paths` (three healthy paths, budgets growing from the floor) asserts `migrates_loop_unfit == 0` — a multi-path scenario, since fit-or-all can never re-stick on the single-path `bulk_bottleneck_single`.

### P4 — Budget round marking

In `send_data` (`streams.rs` L234–254): when `bulk_affinity(sticky)` returned `Some(sticky)` but the room filter rejected it, or when the piece is parked (`budget_waited` branch), call `note_budget_limited()` on the **sticky** (and, as today, on every path with `room_bytes() == 0` when parked). Count `st.budget_diverts += 1` and `metrics.send_budget_diverts += 1` on a divert. `end_budget_round` then sees `limited == true` on a sticky that turned bulk away and runs the growth/probe controller as specified in the predecessor's P2.2. No change to the controller itself. `room_bytes() ≥ 1` overshoot rule unchanged (documented in the predecessor).

### P5 — Fresh-path rehome for every bulk `why`

**Scope (architecture review M4/N7).** P5 applies to **bulk** pieces. Interactive `age` rehomes keep today's behaviour unchanged: they are the product's primary TTFB door, and the stall story P5 answers (79 correlated-silence episodes/h in which 7 of 8 TCPs across 4 ISPs go quiet together) has not yet been shown to be network silence rather than a local or peer-side stall — P1.8 (b) is the discriminator. For the same reason the **all-quiet fallback (KD9) does not ship in PR 2**: it is specified below and lands only if PR 1's data shows `skipped{no_fresh_alt}` pieces waiting past `down_timeout` *and* the survivor's ACK actually returning after fresh-alt rehomes. Until then, when no candidate is fresh the piece waits. For `silence` this is same-or-better than today (TCP delivers the original; no buried copies); for `down`/`gone`/`dropped` today's buried copy is delivered by TCP at hold end whereas the piece now waits until some path is quiet-fresh again (+ probe interval + tick) — same order of magnitude, not identical; watch the age distribution of `skipped{no_fresh_alt}` pieces in PR 2's canary.

In `retry_expired_unacked` (`mod.rs` L769–962), for bulk pieces, with `fresh(p)` = `is_quiet_fresh(p)` (P7) `&& p.is_schedulable()` (which includes `!is_write_stalled()`, `path.rs` L580–582):

1. `cands` = the set `pick_retry_path` can return for this piece before its last rung: alive ∧ `!tried.contains(id)` (rungs 1–4, `scheduler.rs` L653–663; rung 4 is alive-only, rungs 1–3 add schedulable/fresh; `fresh()` below narrows to schedulable anyway; rung 5, L664–670, returns a *tried* non-current path and is accepted when `fresh(alt)`). `any_fresh = cands.iter().any(fresh)` deliberately ignores tried paths: a copy is already on them. The source is in `tried` and is not a candidate — **except** for `why == "dropped"` (the bytes were never on the wire; set by `migrate_send_blocked` failing, `streams.rs` L422–428, by a parked frame dropped on a full bulk queue, `park_stream_data` → `note_data_dropped`, `path.rs` L1089–1099 / `mod.rs` L720–730, and by a failed retry enqueue, L957–960; a full queue does not clear `fresh`): for `dropped`, `cands` = **all** alive ∧ schedulable paths including tried ones (nothing is on any of them), **and `alt` is drawn from the same set** — `pick_min_rx(cands \ {from})` (`scheduler.rs` L673), not `pick_retry_tried(&tried)`, so `any_fresh` and the picker agree (round 5 M4); if `fresh(from) && from.queued_bulk() < chan` (the per-path bulk-queue bound `wait_bulk_send` already uses, L404), re-send on `from` itself first (`alt = from`, no `tried` change); if that `send_on_path` fails, fall through to the `cands` pick **in the same tick** (round 2 M5).
2. Otherwise `alt = pick_retry_tried(&tried)`. If `!fresh(alt)`:
   - if `any_fresh`: `skipped{no_fresh_alt}`, **do not** push `alt` to `tried`, set `retry_not_before = now + retry_after(from)` (re-check next tick; a fresh candidate exists but the picker's score chose a stale one, or the fresh one was write-stalled / queue-full — retries have no budget check, `mod.rs` L1547–1556) — `continue`;
   - else (KD9 all-quiet, **deferred**, see Scope): allow the send only if `now − u.last_sent ≥ down_timeout(from)` (for `why == "gone"`, `from_path == None`, `mod.rs` L849: use `down_timeout(alt)`), otherwise `skipped{allquiet_wait}`; `why = "allquiet"`. Until it ships: `skipped{no_fresh_alt}` and wait.
2b. If `send_on_path(alt)` **fails** (bulk writer full — `congested` is set only for the urgent queue, `mod.rs` L1632–1636, so a full survivor is still schedulable and fresh): today L957–960 pushes `alt` to `tried` and marks `dropped`, which removes the survivor from next tick's candidates and sends the piece down the all-quiet path onto a silent sibling (round 3 M5). **Changed**: do not push `alt`; set `dropped = true`, `retry_not_before = now + retry_after(alt)`, `skipped{queue_full}`. The piece re-tries the same survivor as soon as its queue drains, which under a hold is the only place it can go.
3. On a successful re-send:
   - `why == "belt"`: `retry_not_before = last_sent + retry_after_bulk(from) × 2^(rung−1)` capped at `down_timeout_ceil` — today's rung (L922–933), unchanged;
   - otherwise: `retry_not_before = last_sent + retry_after_bulk(alt)` — the *alt's* silence clock, rung-independent (KD8).
4. `tried` still bounds A3 (`stalled_long && all tried`).

Effect during a correlated hold with one survivor: the piece's source goes quiet at `retry_after_bulk(from)` (≥ `degrade_for`, P6) ⇒ first tick with a fresh candidate (the survivor) re-sends there; total ≈ one silence period instead of 0.3–5 s of rungs. Effect on receiver-drop (`belt`): unchanged. A `dropped` piece whose source is fresh no longer waits on a sibling's freshness (R32/M2).

### P6 — Silence is at least the probe cycle

`retry_after_bulk(p)`: `lo = max(retry_after(p.id), self.degrade_for(&p))`; `hi` unchanged; `clamp(2 · ack_rtt_fresh, lo, hi)` (stale ⇒ `lo`). `degrade_for` / `down_for` become `pub(super)` (they are private to `steer.rs` L741/L745; `retry_after_bulk` lives in `mod.rs` L698). `degrade_for` = `degrade_timeout(cfg, rtt_known, stable_rtt)` = `max(loss_timeout, probe + rtt, ping_interval_max)` ≥ 50 ms on this pool. A piece is hedged for silence only once the session itself would call the path quiet. The belt is unaffected. Interactive `retry_after` is unaffected.

### P7 — One definition of quiet for bulk destinations

`Session::is_quiet_fresh(&self, p)` = `p.last_rx_ago() < self.degrade_for(p)` (a `Session` method, since `degrade_for` is private to `steer.rs` L741; `scheduler::` helpers that need it take a closure or the precomputed bound) — the complement of the P6 silence test and of `maintain`'s own "quiet" set (`steer.rs` L92–96). Used for: `bulk_affinity` (`mod.rs` L573, replacing `is_loss_fresh`), `bulk_overflow_pick`'s freshness filter (`scheduler.rs` L275), `hol_bulk_dest_ok` (L438–443), P3.2/P3.3's dest tests, and P5's `fresh()`. **Not** changed: `is_loss_fresh` in `pick_retry_path` rungs (interactive `age` rehomes keep today's stricter dest test; in steady state `is_loss_fresh ⇒ is_quiet_fresh`, so a rung 1–2 alt is quiet-fresh — during the `stable_up_hold` second after a fast/class RTT rise `loss_timeout(min(fast, class))` can exceed `degrade_for(stable_rtt)` and the two briefly diverge), `loss_fresh_or_all` in interactive picks, `should_rebalance_conn` (interactive HOL), `retry_after` (interactive clock), and every `path_failed` / `down_for` decision. Effect: an idle healthy sticky between Pongs (`last_rx_ago` up to `probe + rtt`) keeps bulk affinity; a path the session would mark degraded loses it — the same instant `maintain` would log "path silent, marking degraded".

## Alternatives Considered

1. **Keep P3b, measure the probe over `4 · loop` instead of `4 · min_rtt`.** Fixes the time base but keeps a ±10 % rate comparison over a window that a single RTO can distort, plus the revert-under-load hazard the predecessor already noted. Rejected.
1b. **Derive the loop from edge hits** (first draft): the elapsed time between advertising an edge and DATA ending on it. Review round 1 (R29): during a hole `send_ack` records a *retreating* edge per out-of-order arrival, later pieces match those and read a few ms; without a hole every in-order 16 KiB arrival matches some ring edge and reads `W / rate`, which after the gain is `2 · W` in every regime — runaway growth. Rejected in favour of the directly measured hole (P2.1).
1c. **Add a loaded in-order term to the loop** (Pong RTT on the arrival path while bulk flows, so that regime (c) recovers P3b's last 8–10 % on a single path). Two problems: the receiver sends no Pings on a path it is receiving on (idle-gated), and the queue a loaded Pong would see is the one the window itself creates (`Q = W/bw − R`), so `target = 2 · bw · (W/bw) = 2W` in every window-limited state — the runaway the existing `rtt_sample_cap` exists to prevent. Rejected; the hole covers the part of the loop that is *not* self-inflicted, and the quiet-RTT fixed point `2 · BDP` already puts throughput at `bw`.
2. **Sender-side window inflation** (sender ignores the advertised window up to some multiple when `window_limited_with_room`). Breaks flow control for a slow app — the one case the window exists for. Rejected.
3. **Exclude unfit paths from bulk entirely.** Starves them (no bulk ⇒ no `ack_rtt` sample ⇒ stays unfit) and creates an all-unfit deadlock. Fit-or-all + `ack_rtt` expiry (KD5/KD7) instead.
4. **Use `tcp_retrans` delta as the unfit signal.** Direct, but Linux-only, sampled every 10 s, and a path with retrans but a short loop (fast-retransmit, deep cwnd) is fine for bulk. `ack_rtt` is what pieces actually experience. Retrans stays informational.
5. **Move pieces off an unfit sticky (migrate unacked).** Duplicates DATA the unfit TCP will still deliver; that is the hedge storm by another name. Re-stick only (KD6).
6. **Shorten `all_down_timeout` / weaken the correlated hold** to end stalls sooner. Retunes a policy field and reintroduces the reconnect storm the hold prevents. Fresh-alt rehome fixes the stall inside the hold. Rejected.
7. **Instrument `HopProbe::poll_*` and infer the blocker from tokio `CopyBuffer`'s polling order** (first drafts, review rounds 1–5). Works only by encoding a third-party implementation detail ("the reader is polled while the writer is Pending", write-wins). Reversed by the architecture review: a ≈ 60-line copier of our own gives exact per-direction waits with no precedence rule (P1.2).
8. **`TCP_CONGESTION=bbr` on the origin socket.** Would help uploads to lossy origins; no evidence yet (P1.5 provides it). Open question, not in scope.

## Security & Privacy Considerations

No new listeners, keys, or TOML. `TCP_INFO` on the origin socket exposes the same kernel counters already exported per path. Span attributes add byte counts and durations only. Memory: P2.4 bounds the window growth per session; a hostile peer can advertise a huge window but the sender's per-path budget (v0.1.6) bounds what it emits.

1. Land PRs in order (below). `cargo test -p nya-core`; `cargo test -p nya-e2e --test matrix short_matrix`; new scenarios; mixed soak: no new SLA red, `failbacks = 0`, no `all_down`.
2. **PR 1 (attribution + falsifiers) ships alone first** and runs 24 h on all three instances. It must answer four questions before anything else ships: (i) are Hytron's slow downloads `origin` or `window/path`? — if ≥ 80 % of ≥ 8 MB slow hops are `origin`, PRs 2–3 still ship (they fix measured defects) but G1 is re-scoped to the non-origin share; (ii) on `limiter = window` hops, is `hole_us` ≫ `rtt` (reorder hole ⇒ P2/P3 story holds) or ≈ 0 (in-order queue / pump ⇒ **P2 and P3 do not ship as designed**; the design is revisited) — this is a cross-role join (`limiter` on the server's sender span, `hole_us` on the client's receiver span) on `session_fp` + `stream_id`; `.local/nya-signoz.py` must be shown to do that join before PR 1 lands, or the null result cannot be read; (iii) do both roles see correlated-silence episodes at the same instant (local/peer stall ⇒ the all-quiet tier stays deferred and P5's value is re-assessed) or does the survivor's ACK return after fresh-alt rehomes; (iv) is `tcp_retrans` directional as the upload/download asymmetry predicts.
3. Canary **Datawave** (interactive + the pzhkt long-lived streams: validates P5/P6/P7 on the stall shape without bulk), 6 h. Then **Yuusei** (slow-origin 248 KB/s streams: validates P6/P7 dup ≤ 2 % and single sticky, leftover/RST invariants), 12 h. Then **Hytron**.
4. Both ends must run the new binary for P2 (receiver) + P4/P5/P6/P7 (sender) to act on both directions; P1/P3 are unilateral.
5. Watch 24 h post-Hytron:

## Risks

| Risk | Sev | Mitigation |
| --- | --- | --- |
| P2 grows the window on a stream whose app *is* the limiter but keeps `app_backlog ≤ cap/2` | Med | An app that keeps up with the arrival rate is not the limiter by definition; one that does not accumulates in-order bytes in `recv_buf` (unbounded, up to the cap) past `cap/2` within one loop and the shrink rule fires. `zero_win_app` on the span shows any residue. |
| P2 monotone-up ⇒ memory per bulk stream up to 8 MiB | Med | Per-session guard `alive_paths · ceil` (P2.4) + gauge; only streams that see holes or run at `> 2 · rate · rtt` grow; growth stops when `target ≤ cur`. |
| Hole sample polluted by hedge copies | Low | Duplicates (`offset < recv_next`, past `close_off`, or already buffered) return before the hole logic (P2.1); a first arrival that *is* the hedge copy closes the hole at the time the stream really waited. |
| Hole sample too short when a second hole sits behind the first (re-opened at the first's close) | Low | Under-estimates only when two independent losses overlap; the next sample corrects; monotone cap means no shrink from an under-estimate. |
| Hole state races between path-reader tasks (one inserts while another drains) | Low | State is derived from buffer contents under the `recv_buf` lock in `drain_recv`, not from the landing offset (P2.1); test `hole_state_from_buffer_under_lock`. |
| `TunnelStream` keeps stream state alive past reap | Med→none | Only `StreamCounters` (atomics) is shared; `inbound_tx`, buffers and `Notify` stay in `StreamState` and drop at `remove_held_stream` as today (KD13); test `tunnel_stream_does_not_hold_inbound_tx`. |
| P7 keeps bulk affinity on a path up to `degrade_for` instead of `loss_timeout` (≈ 50–70 ms vs 20 ms) ⇒ a blackholed sticky is left ≈ 30–50 ms longer | Low | The hedge source clock (P6) is the same `degrade_for`, so the first hedge and the loss of affinity now coincide instead of affinity being lost first; `path_failed` rehome unchanged; `hedge_only_on_silence` door updated. |
| P3 flaps a sticky between two paths whose `ack_rtt` straddle the bound | Med | Re-stick requires `stick_changed_ago_ge(bw_window_us)` and room on the dest; `ack_rtt` is an α = 1/8 EWMA; the bound has ≥ 20 ms of absolute margin (`backup_rtt_add`); unfit ⇒ fit needs `bw_window_us` of silence or samples under the bound. `nya_migrates_loop_unfit_total` is the watch counter. |
| P3 × P4: a healthy sticky whose budget P4 lets grow crosses the fit bound and is re-stuck to an idle sibling at the budget floor | Med | A healthy saturated sticky sits at `≈ 2 · min_rtt`; the bound is `2 · pool_ref + 20 ms ≥ 2 · min_rtt(fastest idle) + 20 ms`, so same-class growth stays fit with ≥ 20 ms margin; `bulk_fanout_three_paths` asserts `migrates_loop_unfit == 0` while budgets grow. |
| P3 calls a healthy saturated path unfit relative to a faster sibling (`3 · min_rtt(p) > 2 · pool_ref + 20 ms` — Hytron's 7–15 ms spread makes this reachable once P4 has grown budgets) ⇒ under fit-or-wait it gets neither home nor overflow and aggregate fan-out shrinks | Med | Bounded in practice: an idle fit path with room absorbs overflow first and `pool_ref` rises as it loads. The existing doors are all equal-RTT, so add e2e `bulk_fanout_rtt_spread` (three clean paths at 7 / 13 / 15 ms, budgets grown): aggregate goodput ≥ 0.9 × the equal-RTT `bulk_fanout_three_paths` figure. If it fails, the knob is `backup_rtt_add` (the `+ 20 ms`), not the fit-or-wait rule (architecture re-review N2). |
| P3 under pool-wide congestion: with the relative bound the least-bad loaded path is always fit, so a home always exists; overflow onto the others is fit-or-wait, so a stream runs at Σ fit paths' delivery rather than spreading onto recovering ones | Low | Intended (KD5). If it ever under-delivers vs today (`bulk_bottleneck_lossy_sibling` goodput door, Hytron canary throughput), the knob is the `is_backup` scale, not the fit-or-wait rule. |
| Kernel BBR ProbeRTT (cwnd → 4 segments for ≈ 200 ms every 10 s on flows whose min-RTT filter is not refreshed) perturbs `ack_rtt` for P3 and P6 | Low | The 1/8 EWMA damps one episode; watch `nya_path_loop_unfit_total` per path for 10 s periodicity in the PR 5 canary (architecture review N3). |
| P2's bet: all loop excess this stream did not create shows up as a *reorder* hole; in-order excess on a shared sticky (other streams' bytes in the same budget, > 1 RTT at low bw) is invisible to `hole` and returns the floor lock there | Med | Stated as the bet; alarm = `limiter = window ∧ hole_us ≈ 0` on ≥ 8 MB hops (P1.8 (a), measured before P2 ships). |
| Reverse bulk on a path inflates its forward `ack_rtt` (ACK behind the reverse `NOTSENT_LOWAT` queue) ⇒ P3 over-calls unfit on bidirectional pools | Med | Fit-or-all for homes + per-stream/per-dest holds bound it to today's placement; e2e `bulk_bidirectional_same_pool` door; if it bites, the forward-only alternative is `ack_rtt` from pieces whose ACK path carried no bulk in the last `rtt` (Open Questions). |
| P4 marks the sticky limited too often ⇒ budget grows on a path whose TCP cannot use it | Med | Growth is still gated by the round controller's step test (bandwidth must follow); `BUDGET_CAP_GAIN · bw_max · min_rtt` caps it; `tcp_notsent` stays the kernel-side check. |
| P5 with `any_fresh` true but the only fresh candidate has no `room` ⇒ piece waits | Low | `fresh()` already excludes write-stalled and non-schedulable paths from `any_fresh`; wait is re-evaluated every `maintain` tick; `retry_not_before = now + retry_after(from)` keeps it in the due set; the belt still fires on the source if it is fresh. |
| P5 all-quiet fallback (deferred) too slow (one copy per `down_timeout`) | Low | All-quiet means teardown is imminent (`down_for` on every path) and `path_failed` rehomes on death; the fallback only covers the hold window. |
| P6 raises hedge latency for genuinely blackholed paths from 20 ms to ≥ 50 ms | Low | `degrade_for` is the session's own quiet clock; interactive pieces keep `retry_after`; `path_failed` rehome unchanged. |
| `TCP_INFO` on the origin socket after `copy_bidirectional` returns `Err` (socket reset) | Low | `getsockopt` on a reset socket still returns the last state; on `EBADF`/error the attribute is absent. |
| P1.2 wait accounting depends on how the copier interleaves reads and writes | Low→none | The timed copier is ours (P1.2): per direction exactly one await is outstanding at a time, so each wait is billed to one side by construction; `timed_copier_bills_one_side` asserts it. |
| `n_counter` / catalog drift | Med | Each PR updates `n_counter`, the catalog test and `.local/nya-signoz.py completeness`. |
| Old `nya.limiter` dashboards see new values | Low | Old values keep meaning; docs updated. |

## Open Questions

- `TCP_CONGESTION=bbr` on the server's origin socket for uploads — decide on P1.5 evidence (`rwnd_limited` vs `busy_time` vs retrans).
- Whether `loop_fit` should also feed `path_score`'s `load_term` for **interactive** placement. No: interactive affinity already avoids write-stalled paths and its RTT class is quiet RTT by design; revisit only if interactive TTFB p99 correlates with `loop_fit = 0` paths.
- P2's `2×` gain: the base formula has always used 2 (BBR cwnd_gain); with the loop measured it may be conservative for reorder holes deeper than one loop. Watch `zero_win_hole` on large hops.
- **Window-update ACK path.** The cumulative ACK that re-opens the window after a hole fills rides the reverse direction of the very TCP that just had the RTO (`drain_recv(st, ack_path)`). Sending window-updating ACKs on the freshest alive path is wire-compatible (ACKs are cumulative + SACK) and ≈ 10 lines; it shortens the loop P2 measures around. Not in this design — decide on `hole_us` vs `ack_loop_ms` correlation after PR 1 (architecture review N2).
- **Forward-only `ack_rtt`.** If `bulk_bidirectional_same_pool` shows P3 over-calling unfit, sample `ack_rtt` only from pieces whose ACK path carried no reverse bulk within the last `rtt` (existing per-path `tx` clock), or compare `ack_rtt − reverse_queue_estimate`.
- **Fewer, fatter TCPs.** The strategic direction named in "Root cause, one level down": a scheduler whose default is one flow per bulk stream, growing to a second only when the first is at its budget ceiling and the window is still limited. Out of scope; P4/P7 move toward it, P3.2's fit-or-wait does not move away.

## Tests required

Unit (`nya-core`):

- `tunnel_stream_stats_survive_reap`: reap the stream, `TunnelStream::stats()` still returns the final counters.
- `tunnel_stream_does_not_hold_inbound_tx`: fill the inbound channel, deliver Close (dropped by `try_send`), `remove_held_stream` ⇒ the pump's recv loop ends (`None`) while a `TunnelStream` is still alive.
- `timed_copier_bills_one_side`: a direction whose writer blocks for 100 ms while the reader has data ready accrues 100 ms `write_wait` and 0 `read_wait`; the mirror case accrues `read_wait` only; the two directions' waits are independent; byte counts and `first_rx`/`first_tx` equal `tokio::io::copy_bidirectional`'s on the same input.
- `timed_copier_close_semantics`: EOF on one side shuts down the other side's writer exactly as `copy_bidirectional` does (the Yuusei leftover/RST invariants depend on this); error on either side returns the same `Err` and the partial counts.
- `limiter_by_time_*`: one case per row of the P1.3 table × {far-dominant, near-dominant}: server download ⇒ `origin` / `window|budget|path`; server upload ⇒ `overlay` / `origin`; client upload ⇒ `app` / `window|budget|path`; client download ⇒ `overlay` / `app`; plus the `none` threshold.
- `origin_tcp_info_on_hop`: server hop carries `nya.origin_tcp_*` when the origin is a real Linux socket; absent on a failed dial.
- `aggregate_snapshot_merges_every_histogram`: two sessions each observe one sample into every `HistSnap` field; the aggregate has `count == 2` for each (field list via `hist_fields_mut`).
- `hist_merge_adopts_when_empty`.
- `recv_cap_max_observed_at_stream_end`.
- `hole_sample_open_close`: piece at `recv_next + 16 KiB` lands at t0 (drain sees a missing head ⇒ hole opens at `recv_next`), piece at `recv_next` lands at t0 + 150 ms ⇒ drain delivers both ⇒ `hole_ewma ≈ 150 ms`, `hole == None`; a duplicate of an already-buffered piece in between changes nothing; a head re-inserted by a full channel neither opens nor prolongs a hole; a hole filled by a drain that then stops on a full channel — after delivering some pieces, **or on the filling piece itself** — is sampled by *that* drain (sample excludes the app-blocked interval).
- `hole_sample_second_hole_reopens`: pieces at +16 K and +48 K missing; +16 K lands ⇒ one sample, `hole` re-opened at the new `recv_next` (+48 K); +48 K lands ⇒ second sample, `None`.
- `hole_state_from_buffer_under_lock`: two tasks insert out of order (the round 2 M1 interleavings: second piece lands before the first's drain; head inserted but not yet drained when a further piece lands) ⇒ no orphaned `Some`, no missed open, samples equal the head's actual wait.
- `window_target_uses_rtt_plus_hole`: `rate = cap / (rtt + hole)` ⇒ `target = 2 · cap`; `hole` stale after `8 · loop` ⇒ `target = 2 · rate · rtt`.
- `window_grows_while_app_keeps_up`: window-limited rounds with holes and `app_backlog` small ⇒ cap grows monotonically to `≥ 2 · floor` within 16 samples and until `target ≤ cur`, then holds; the same result whether `tune_recv_cap` is driven by `note_deliver` samples or by 5 ms `maintain` ticks in between; no growth without holes at `rate · rtt < floor / 2`.
- `window_shrinks_only_when_app_behind`: `app_backlog > cap/2` (in-order bytes held in `recv_buf` because the channel is full) ⇒ `cap = min(cur, max(target, held))`, never above `cur`, `advertised_window() ≥ 0`; out-of-order bytes alone (`hole_bytes` large, `app_backlog` small) do **not** shrink or block growth.
- `app_backlog_counts_in_order_run`: `in_order_held` equals the contiguous run at `recv_next`; `hole_bytes = recv_buffered − in_order_held`.
- `recv_cap_extra_released_on_drop`: stream grows to `4 × floor`, closes gracefully (both FINs, `maybe_count_graceful` path) ⇒ `recv_cap_extra` back to 0 once the last `Arc<StreamState>` drops; same via `finish_stream`; a `tune_recv_cap` racing the removal (held `Arc`) is accounted.
- `window_growth_bounded_by_session_room`: 3 streams, 1 path ⇒ Σ extra ≤ 8 MiB; a fourth stream growing, or `alive_paths` dropping to 0, never lowers an existing cap; single stream, one path reaches the full 8 MiB ceil.
- `recv_cap_extra_telescopes_under_concurrent_tune`: two tasks call `tune_recv_cap` concurrently for 10⁴ rounds ⇒ `recv_cap_extra == Σ (recv_cap − floor)` exactly after each round and 0 after all streams drop.
- `loop_fit_bound_and_expiry`: pool of {idle 13 ms, loaded 26 ms, loaded 170 ms} ⇒ `pool_ref = 13 ms`, bound 46 ms ⇒ fit, fit, unfit; pool of {loaded 170 ms, loaded 190 ms} ⇒ `pool_ref = 170 ms` ⇒ both fit (least-bad is fit); single path ⇒ fit; a path with RTT unknown does not make `pool_ref` `None`; the 170 ms path stays unfit after 20 s of steady state (no normalisation — the round 4 B1 case); a path with bytes outstanding and no ACK for 300 ms reads `sojourn ≥ 300 ms` ⇒ unfit even with no `ack_rtt` sample (round 5 M1); after `bw_window_us` with `inflight == 0` ⇒ `ack_rtt_fresh = None`, `carried`/round length fall back, `retry_after_bulk` still reads the retained value.
- `restick_once_to_faster_idle_sibling`: 7 / 13 ms same-class pool, stream on the 13 ms path with its budget grown to the cap ⇒ exactly one `loop_unfit` move to the 7 ms path, then stable.
- `bulk_pick_prefers_fit` (drives the first-bulk-piece path: `becoming_bulk` on an unfit sticky with a fit sibling ⇒ sticky moves once, `migrates_loop_unfit == 1`), `bulk_overflow_prefers_fit`, `fit_or_all_when_none_fit`; `close_reset_pick_ignores_fit`: `pick_pref(Any)` for Close/Reset and `failback_target` return the same path with and without an unfit member.
- `bulk_restick_off_unfit_sticky`: sticky unfit, never-loaded sibling with room ⇒ sticky moves once, `migrates_loop_unfit == 1`, `hol_rebalances` unchanged, no DATA re-sent; no second move within `MIN_RTT_WIN_US`; two paths that are both unfit once loaded (F saturated by another stream, A/B at 60 ms) ⇒ the stream **stays put** (the drained path keeps its last verdict; round 5 M2).
- `budget_limited_marked_on_divert`: sticky at budget, sibling with room ⇒ piece diverted, `round_limited` true on sticky, `budget_diverts == 1`; `end_budget_round` grows budget when bandwidth steps.
- `rehome_waits_for_fresh_alt`: source silent, all alts silent but one fresh ⇒ re-send goes to the fresh one on the first due tick; `skipped{no_fresh_alt}` counts the ticks before it had room.
- `rehome_any_fresh_over_candidates_only`: source fresh but silent-for-hedge is impossible under P7 (same clock), so: `why == "down"`, source dead, one fresh sibling and one silent sibling in `tried` ⇒ `any_fresh` true and the fresh sibling is used; with the fresh sibling also in `tried` ⇒ `any_fresh` false ⇒ all-quiet path.
- `dropped_piece_resends_on_fresh_source`: `dropped = true`, source fresh with queue room, sibling silent ⇒ re-sent on the source, `tried` unchanged, no skip; source fresh but `queued_bulk == chan` ⇒ falls through to the `cands` pick in the same tick; `tried = [A, B]`, A fresh again, B/C quiet ⇒ `alt = A` (picked from `cands`, not `pick_retry_tried`), no perpetual skip (round 5 M4).
- `rehome_all_quiet_once_per_down_timeout`: no fresh candidate ⇒ exactly one `allquiet` re-send per `down_timeout`; `why == "gone"` uses `down_timeout(alt)`.
- `retry_enqueue_failure_keeps_alt_untried`: survivor's bulk queue full ⇒ `send_on_path` fails ⇒ `alt ∉ tried`, `dropped`, `skipped{queue_full}`; queue drains ⇒ next tick re-sends on the survivor, never `allquiet`.
- `silence_rehome_rearms_on_alt_clock`: after a silence re-send, `retry_not_before − last_sent == retry_after_bulk(alt)` regardless of `tried.len()`; belt still doubles.
- `retry_after_bulk_at_least_degrade`: `ack_rtt = 10 ms`, `ping_interval_max = 50 ms` ⇒ `retry_after_bulk ≥ degrade_for`.
- `quiet_fresh_between_pongs`: idle path, `last_rx_ago = probe + rtt − ε` ⇒ `is_quiet_fresh` true while `is_loss_fresh` may be false; `bulk_affinity` keeps the sticky; at `degrade_for` both `is_quiet_fresh` and `maintain`'s quiet set flip together.

- `stall_enter_kind_recorded`, `resend_why_recorded`, `zero_window_cause_split`.
- `n_counter` / catalog updated in each PR.
